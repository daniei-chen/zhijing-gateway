# v0.0.3 候选 · 会话稳固，等待可见

延续智境的紫蓝青、液态玻璃与原有工作台布局，本轮集中修复认证边界、后台加载和图片任务生命周期，并细分首响应诊断。

**状态：本地验证候选，供草稿 PR 审查；没有发布正式 v0.0.3 Release，也没有替换线上。** 全局四项覆盖率仍未达到 80%，生产 TTFT 改善也尚未验证。

| 改进 | 实际行为 |
| --- | --- |
| 凭据留在浏览器 Cookie | 匹配后端支持时，真实访问与刷新凭据改为 HttpOnly Cookie；前端只保存不能单独认证的会话选择符。保留旧 Bearer/API Key 客户端。 |
| OAuth 登录不带 URL 凭据 | GitHub、Google、LinuxDo、OIDC 服务端登录改走浏览器绑定、一次性待完成会话；五种前端回调拒绝原始 access/refresh token，并约束晚到的异步结果。 |
| 撤销与认证存储 | 原子轮转、用户代际和会话撤销；OAuth 与管理员长连接复验。启动检查要求不可淘汰、同步 AOF 和正常持久化状态。 |
| 表单与键盘操作 | 取消重开、换目标与换登录的旧结果不写回新草稿；字段命名、禁用、清空、选择及手机焦点有实际 DOM 回归。 |
| 找回密码归属明确 | 验证码等待期间锁定提交、绑定原邮箱与会话，离开页面或换号后不再写回旧结果。 |
| 图片任务及时清理 | 请求取消、串行轮询、选择切换、下载和缩略图资源各自有归属；缓存有条数、体积与时间上限，换号清空。 |
| 后台按需加载 | 账号弹窗、设置面板、分组重组件延后加载；设置页已访问面板保留未保存内容。弱网、省流、离线和后台标签限制路由预取。 |
| 首响应可细分 | 展示上游请求写完、首字节、响应头、首事件，以及有内容输出到达和成功刷新的时间。原 TTFT、计费、权限和模型选择保持。 |
| 发布口径一致 | 延续原始兼容摘要链，增加明确的 v0.0.3 审阅记录；打包选择匹配版本后端补丁，CI 与打包都执行四项 80% 覆盖率门槛。 |

- 11 月 6 日冻结检查点 10：前端 **486 个测试文件、5,015 项测试通过**；类型检查、全仓 ESLint 与 `vite build --manifest` 通过。设置批次收尾、支付表单、账号列表、运维设置和兑换码弹窗修复已纳入本次完整回归。
- 检查点 10 覆盖率：行 **80.97%**、语句 **78.40%**、函数 **72.00%**、分支 **69.84%**；后三项仍未达到原 80% 门槛，覆盖率命令退出 1。检查点 09 的缺失翻译失败与修正记录保留，不把失败运行当成覆盖率通过。
- 兑换码的生成、批量修改及结果弹窗统一使用玻璃风格共用组件，保留原业务表单。真实浏览器验证生成弹窗的初始焦点、双向 Tab 循环、下拉框先于外层响应 Escape，以及 390/320px 内滚动；没有进行真实生成或删除。
- 顶部栏退出归属、备份的二次验证提交快照与迟到反馈还有已复现问题，正在下一轮修复；本检查点不代表发布门禁全部通过。
- 已验证后端 `869d91f…` 的完整 `-tags unit -short ./...`：64 个有执行包通过，12,557 个顶层测试、25,189 个含子测试通过事件，39 个测试事件跳过；另有 51 个无执行包。Go vet、匹配 181 文件内嵌资源的 Linux amd64 构建通过。83 文件干净基线的 12 包扩大定向 race 通过，1,234 个顶层测试、2,313 个含子例通过事件、14 个条件跳过；四个不相交名称批次均退出 0，包按唯一值计数。
- 后端差异在干净基线成功应用并核对结果摘要；公共 CI 只验证补丁，不能替代完整私有后端编译。
- 内置浏览器使用合成账号验证登录、刷新恢复、跨标签换号离开旧管理员路由，以及设置页切换后草稿保留。未执行真实邮件、付款或供应商推理。

## 升级约束

先验证并升级[匹配后端](../../integrations/sub2api/v0.0.3/README.zh-CN.md)，再更新前端。新前端拒绝 URL 登录凭据，不能与旧后端的原始 token OAuth 回调混用。旧浏览器凭据可在匹配后端广告 Cookie 能力后迁移；跨域旧客户端保持 Bearer 模式。

本候选不改变套餐、金额、额度、并发上限或推理档位。只读样本仍出现长上传与首输出等待，尚未部署的新里程碑用于进一步区分阶段；**未宣称生产 30 秒延迟已修好**。独立分位数不能相减以定位单条请求，较大的未压缩上传仍需客户端与上游协议分别验证。

新增[可选本机上传压缩](../clients/upload-relay.zh-CN.md)及 24 项真实回环 HTTP 回归，尚无生产效果对照。新后端认证存储的同步落盘条件需要隔离验证并落实；不会自动改线上 Redis。

完整依据、复现命令与未完成项见[最新修复记录](../reviews/2026-11-06-v003-followup.zh-CN.md)和[机器可读验证摘要](../validation-v0.0.3.json)。[11 月 5 日检查点](../reviews/2026-11-05-v003-repair.zh-CN.md)和历史 [v0.0.2 发布](https://github.com/daniei-chen/zhijing-gateway/releases/tag/v0.0.2)保留原口径。
