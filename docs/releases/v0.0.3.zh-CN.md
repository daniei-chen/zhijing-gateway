# v0.0.3 候选 · 会话稳固，等待可见

延续智境的紫蓝青、液态玻璃与原有工作台布局，本轮集中修复认证边界、后台加载和图片任务生命周期，并细分首响应诊断。

**状态：本地验证候选，供草稿 PR 审查；没有发布正式 v0.0.3 Release，也没有替换线上。** 全局四项覆盖率仍未达到 80%，生产 TTFT 改善也尚未验证。

| 改进 | 实际行为 |
| --- | --- |
| 凭据留在浏览器 Cookie | 匹配后端支持时，真实访问与刷新凭据改为 HttpOnly Cookie；前端只保存不能单独认证的会话选择符。保留旧 Bearer/API Key 客户端。 |
| OAuth 登录不带 URL 凭据 | GitHub、Google、LinuxDo、OIDC 服务端登录改走浏览器绑定、一次性待完成会话；五种前端回调拒绝原始 access/refresh token，并约束晚到的异步结果。 |
| 找回密码归属明确 | 验证码等待期间锁定提交、绑定原邮箱与会话，离开页面或换号后不再写回旧结果。 |
| 图片任务及时清理 | 请求取消、串行轮询、选择切换、下载和缩略图资源各自有归属；缓存有条数、体积与时间上限，换号清空。 |
| 后台按需加载 | 账号弹窗、设置面板、分组重组件延后加载；设置页已访问面板保留未保存内容。弱网、省流、离线和后台标签限制路由预取。 |
| 首响应可细分 | 展示上游请求写完、首字节、响应头、首事件，以及有内容输出到达和成功刷新的时间。原 TTFT、计费、权限和模型选择保持。 |
| 发布口径一致 | 延续原始兼容摘要链，增加明确的 v0.0.3 审阅记录；打包选择匹配版本后端补丁，CI 与打包都执行四项 80% 覆盖率门槛。 |

## 验证结果

- 前端 **418 个测试文件、3,290 项测试通过**；类型检查、全仓 ESLint、静态构建和兼容契约检查通过。
- 覆盖率：行 **67.52%**、语句 **65.42%**、函数 **52.18%**、分支 **54.69%**；覆盖率命令因四项门槛不足退出 1。
- 匹配后端的 handler、service、server、pkg、repository 短回归通过；会话、OAuth、时序和流式输出定向 race、Go vet、Linux amd64 交叉构建通过。
- 后端差异在干净基线成功应用并核对结果摘要；公共 CI 只验证补丁，不能替代完整私有后端编译。
- 内置浏览器使用合成账号验证登录、刷新恢复、跨标签换号离开旧管理员路由，以及设置页切换后草稿保留。未执行真实邮件、付款或供应商推理。

## 升级约束

先验证并升级[匹配后端](../../integrations/sub2api/v0.0.3/README.zh-CN.md)，再更新前端。新前端拒绝 URL 登录凭据，不能与旧后端的原始 token OAuth 回调混用。旧浏览器凭据可在匹配后端广告 Cookie 能力后迁移；跨域旧客户端保持 Bearer 模式。

本候选不改变套餐、金额、额度、并发上限或推理档位。高 TTFT 的只读样本主要等待上游响应头之后的有效输出，新诊断只能增加可解释性；**未宣称生产 30 秒延迟已修好**。较大的未压缩上传仍需客户端与上游协议分别验证。

完整依据、复现命令与未完成项见[修复记录](../reviews/2026-11-05-v003-repair.zh-CN.md)和[机器可读验证摘要](../validation-v0.0.3.json)。历史 [v0.0.2 发布](https://github.com/daniei-chen/zhijing-gateway/releases/tag/v0.0.2)及审计证据保持原样。
