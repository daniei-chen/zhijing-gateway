# 可选本机上传压缩中转

部分客户端会把完整上下文作为较大的 identity JSON 上传。这个可选工具先在本机压缩，再通过网络发送到明确配置的智境站点；它针对的是**客户端至网关的上传字节数**。网关收到完整请求后才进行上游转发，所以这里的节省不等于模型推理加速，也不证明生产 Forward TTFT、端到端 TTFT 或首输出长尾已经改善。

工具只使用 Python 标准库，不安装依赖。它不读取或自动修改客户端配置，不配置 API Key，也不自动修改 Magpie。先由使用者确认所选网关入口支持 gzip 请求体；匹配的智境后端已有该解码能力，其他代理或服务不能直接据此推定支持。

## 启动与接入

在仓库根目录运行，使用 Python 3.10 或更新版本。本轮实际验证环境为 Python 3.12.10。

```powershell
python tools/upload_relay.py --upstream https://gateway.example --listen-port 8787
```

将 `https://gateway.example` 替换为自己明确选择的 HTTPS 网关**站点 origin**。该参数不能包含用户名、密码、路径、查询参数或片段；不要附加 `/v1`，不要把密钥放在命令行或 URL 内。工具保持系统 CA 和域名校验，没有跳过证书验证的开关。

对于原先使用下列地址的 OpenAI 兼容 HTTP 客户端，只需在客户端自己的设置界面手动修改 Base URL：

| 设置 | 原值示例 | 启用本机中转后 |
| --- | --- | --- |
| 客户端 Base URL | `https://gateway.example/v1` | `http://127.0.0.1:8787/v1` |
| 客户端 API Key、模型和推理参数 | 已有配置 | 保持原值 |
| 中转的固定上游 | 无 | 启动参数中的 `https://gateway.example` |

路径为：`客户端 → 127.0.0.1:8787 → 固定 HTTPS 网关 → 原上游`。客户端继续随每个请求发送自己的 `Authorization`，中转将该字段原样传给固定网关，由网关执行真实认证。没有认证字段的调用在本机返回 401；回环端口本身不是匿名业务入口。

当前版本适用于携带 `Authorization` 的客户端；只有 `x-api-key`、没有 `Authorization` 的客户端不纳入该工具的接入范围。

停止时按 `Ctrl+C`。停止或客户端断连会关闭在途连接；工具不会重发可能已经计费的请求，也不会替网关回滚已有用量。恢复原来的客户端 Base URL 即可绕过中转。

## 压缩与流式响应

默认收到至少 32 KiB 的 `application/json`（允许 `charset` 参数）且 `Content-Encoding` 为空或 `identity` 时，工具尝试 gzip level 3。只有结果比原请求更小时才使用压缩，并重算 `Content-Encoding` 和 `Content-Length`。小请求、不划算的压缩、非 JSON，以及已有 gzip、zstd 等编码的请求保持原传输字节。

工具不解析、重新序列化或裁剪 JSON，不改模型、effort、提示词、上下文、工具声明或流式选项；不做并行试探、重试或降档。已编码请求不在本机解压，网关继续负责解码与解压后的大小检查。

响应使用 `read1` 读取当前可用片段并立即写出、flush；不会等待填满 64 KiB 或等待上游结束才交付第一条 SSE。SSE 事件内容和顺序保持原样；HTTP 层必要时重新分块。上游状态码和错误体继续传回。发生截断时不会补造成功事件或正常结束块；客户端可以观察传输失败。

每次调用使用独立上游连接，双方连接在请求完成后关闭。它增加了本机压缩、内存和连接建立开销，因此是供大上传场景选择的工具，不保证每个请求都更快。

## 接口与资源边界

中转只监听 `127.0.0.1`，要求 `Host` 精确匹配本机端口。带 `Origin`、`Referer` 或 `Sec-Fetch-*` 的网页请求被拒绝，不提供 CORS。不要把该端口再暴露到公网或供浏览器页面访问。

仅允许以下路径与方法，查询参数原样传递到同一固定上游：

| 方法 | 路径 |
| --- | --- |
| GET | `/v1/models` |
| POST | `/v1/responses`、`/v1/responses/compact` |
| POST | `/v1/chat/completions`、`/v1/completions`、`/v1/embeddings` |
| POST | `/v1/messages`、`/v1/images/generations` |

管理员、登录和其他路径不转发；不支持 CONNECT、WebSocket、HTTP Upgrade、HTTP/2 或任意目标地址。使用本工具的客户端须能发送 HTTP/1.1。工具自身不跟随上游重定向；下游收到的重定向仍由客户端决定如何处理。

POST 必须提供一个有效的十进制 `Content-Length`。不接受 chunked 请求体、`Transfer-Encoding`/`Trailer`、重复的关键头、折叠头或其他含糊分帧。有效的 `Expect: 100-continue` 会在本机边界检查后才允许上传。长度不足返回 400，上传超时返回 408，超限返回 413；客户端在发送超大体时也可能先观察到连接关闭。每个连接只处理一次请求，额外数据和流水线请求不会变成第二次上游调用。TCP 写半关闭视为取消，不支持以半关闭代替请求长度。

双方 hop-by-hop 头及 `Connection` 列举的头都会剔除。上游重复长度、TE/CL 冲突等含糊响应在转发前返回 502；转发已开始后的异常以断流呈现，不在原响应后追加另一种错误格式。

| 默认限制 | 数值 | 调整参数 |
| --- | ---: | --- |
| 请求头总字节数 | 32 KiB | 固定 |
| 收到的请求体 | 16 MiB | `--max-body-bytes`，最多 64 MiB |
| 尝试压缩的最小体积 | 32 KiB | `--compress-min-bytes` |
| 同时处理的连接 | 4 | `--max-connections`，最多 32 |
| 请求头及上传总期限 | 60 秒 | `--upload-timeout` |
| 上游 socket 空闲等待 | 300 秒 | `--upstream-timeout` |
| 下游写等待 | 30 秒 | `--write-timeout` |
| 单次转发总期限 | 3,600 秒 | `--max-stream-seconds` |

体积上限检查发生在压缩之前；即使超大 JSON 有望压小，也不会越过该内存边界。每个请求会在内存保留完整原始体及压缩候选，选择并发数时需考虑这一成本。超出并发上限返回 503。超时与断流不触发重试。

中转不输出逐请求日志，不持久化凭据或请求体，不启用环境变量中的 TLS key log。启动消息只显示本机监听地址。HTTP 仅供仓库内部合成测试，并且只允许字面回环 IP；命令行没有启用不安全 HTTP 上游的选项。

## 本地验证与证据边界

```powershell
python -m unittest tools.tests.test_upload_relay -v
```

回归使用真实回环 HTTP echo 和接收端节流，比较接收的 wire 字节、解压后逐字节与 SHA256，并检查首条 SSE 在上游仍开放时可读、取消释放、截断、认证、走私边界、超限与日志。无需提供网关密钥，不调用供应商模型。

一次 Windows / Python 3.12.10 合成运行的示例结果：5,500,012 字节的重复文本 JSON，identity 上传 5,500,012 字节，gzip 上传 34,743 字节，解压后完全一致。同一节流接收端读入约 823.72 ms 与 7.14 ms。这些数字只描述该合成数据和接收端节流；图片、已压缩内容、真实网络和真实上下文的比例可能不同。测试会打印当次 `SYNTHETIC_UPLOAD_PROOF`，不把它当作生产或供应商 TTFT 基准。

生产效果仍需在实际客户端、固定网关及反代入口上核验：上传编码、wire 字节和请求体读入时间应分别对照；模型、账号和上下文保持一致，另看上游首输出及下游收到首事件的里程碑。没有这样的匹配对照前，不宣称此前 128 秒上传、244 秒截断或上游长尾已被解决。
