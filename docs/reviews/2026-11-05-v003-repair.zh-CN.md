## 1. 修复范围

本记录承接[严格审计终稿](2026-11-05-strict-audit.zh-CN.md)。其中浏览器依赖路径、测量 manifest 计数、9 项冒烟范围、交接草稿 TTL、CPU 中位耗时比、Go 探针执行状态与复制重试键身份条件等七处说明已在继承分支修正。历史证据与基线不改写为本轮结果。

| 原问题 | 本轮处理与验证 |
| --- | --- |
| AUTH-R01：OAuth URL 登录凭据 | 后端现有用户路径统一暂存为浏览器绑定的待完成会话；原先预签发且未交付的刷新凭据撤销。前端五种回调清理片段、拒绝可复用 token；异步操作只完成自身会话。四种后端提供方完成绑定、错浏览器、重放与到期测试。 |
| AUTH-R02：JavaScript 长期凭据 | 新增显式选择的 Cookie 适配层，同源 HTTPS 浏览器接收 HttpOnly、Secure、SameSite=Strict、host-only Cookie；真实 JWT 仍经过原鉴权。前端保存的公开选择符缺少 Cookie 时不能认证。登录、轮转分开 Cookie 名称，晚到响应不能覆盖新会话所选凭据。 |
| AUTH-R03：找回密码 CAPTCHA 竞态 | 提交锁在等待证明之前建立；请求绑定原邮箱与会话，离开页面及账号变化后忽略结果。保留既有 CAPTCHA 提交流程。 |
| 图片资源、缓存与轮询 | API 调用和完整响应体读取绑定原会话及 AbortSignal；页面任务、选中任务和预览各自校验归属。串行轮询不重叠；图片缓存仅在内存，默认 120 条、24 MiB、30 分钟，换号清空；旧共享磁盘缓存不读取并尝试删除。缩略图 Bitmap/Object URL、关闭弹窗与卸载均清理。 |
| 预取与重页面加载 | 省流、离线、后台标签、慢连接及空闲预算不足时不预取；账号弹窗、设置及分组组件按需加载。设置标签首次进入后保留组件与未保存内容。 |
| BACK-R01：请求 ID 淘汰后误归因 | 有界退休标记覆盖关联时间窗口；重复 ID、无效 ID、容量不足时拒绝不可靠关联。保持用户及 Key 范围；只影响诊断，不改变授权和请求调度。 |
| TTFT 阶段不够细 | 记录请求写完、首字节、首事件、有内容输出到达与成功刷新的时间；累计里程碑与阶段耗时分开呈现，缺失保持未知，保留原 TTFT。两个 Responses 流转路径测试证明有内容事件在上游连接仍打开时就向下游刷新。 |

浏览器 Cookie 协议是配套前后端安全变更，不能概括成纯 UI 更新。未选择该模式的旧 Bearer/API Key 客户端继续走原协议；尚未升级后端或跨域的旧浏览器模式仍可能保留原凭据。HttpOnly 不等于解决全部同源脚本风险。

## 3. 高 TTFT 的证据与未完成项

用户观察值：TTFT P99 30,354 ms、P95 27,482 ms、P50 5,006 ms、平均 8,475 ms、最大 35,087 ms。下表来自 2026-11-05 22:18 CST 的最近一小时只读聚合：107 条精确关联请求，均为 OAuth 账号；不含原始日志、用户、密钥或提示词。

| gpt-6.1-sol 样本 | 数量 | TTFT P50 | 上游响应头 P50 | 响应头至首语义事件估计 P50 | 本地规范化 P50 |
| --- | ---: | ---: | ---: | ---: | ---: |
| medium | 34 | 15,537.5 ms | 3,099.5 ms | 12,467.5 ms | 4 ms |
| high | 61 | 4,356 ms | 1,887 ms | 2,349 ms | 1 ms |

这两个分组请求内容不同，**不能据此证明 high 比 medium 更快**。各列中位数单独计算，不能用中位数相减或相加复原请求。响应头后残余包含传输及本地处理，不能直接命名为模型推理耗时。

相邻窗口 113 条样本均 HTTP 200、未见传输错误，连接等待中位数为 0；服务器负载与资源未见耗尽。它们不代表历史错误全部消失，也不能单凭资源空闲确定供应商原因。

另观察到较大的 identity 未压缩上传，部分请求读取请求体达到数十秒。上传与上游首输出是不同阶段；网关收到请求之后再压缩，不能消除客户端已经花掉的上传时间。[官方 Responses 文档](https://developers.openai.com/api/docs/guides/latency-optimization)说明的 API 请求压缩能力，不能直接外推为当前 ChatGPT OAuth 上游或喜鹊自定义转发一定支持。

**已处理**：有界且可靠的关联、可细分的里程碑、流式早刷新回归、后台重复轮询及无效预取。**尚未处理完**：生产首个有效输出长尾、客户端大体积上传、四项全局覆盖率门槛。没有供应商推理压测、上线后前后对比，也没有修改模型、effort、服务档位、额度或并发来制造提速数据。

后续性能验收需要在相同请求、账号和上下文条件下对照新增里程碑，再决定修传输、代理还是上游路径；涉及上游的对照请求会消耗额度，不能把公网 RTT 探测写成推理速度测试。当前版本不能宣称“30 秒已降低到某值”或“全部问题已解决”。

## 4. 复现与交付约束

使用 Node.js 24、pnpm 9.15.9、Python 3：

```bash
corepack pnpm@9.15.9 --dir frontend install --frozen-lockfile
corepack pnpm@9.15.9 --dir frontend typecheck
corepack pnpm@9.15.9 --dir frontend lint:check
corepack pnpm@9.15.9 --dir frontend test:coverage --maxWorkers=4
# 当前覆盖率命令按门槛退出 1；以下构建与检查可分别复验。
corepack pnpm@9.15.9 --dir frontend exec vite build --manifest
python3 tools/verify_frontend.py
node tools/verify_ops_contract.mjs
node --test tools/tests/test_ops_contract.mjs
python3 -m unittest discover -s tools/tests -v
python3 integrations/sub2api/check_patch.py --bundle v0.0.3 --artifact-only
```

后端命令和精确摘要见[匹配补丁说明](../../integrations/sub2api/v0.0.3/README.zh-CN.md)。前端受保护文件变更登记见[明确审阅链](../security-changes-v0.0.3.json)，本历史检查点源码摘要与结果见[验证摘要](../validation-v0.0.3-20261105.json)。公共材料只包含通用补丁、合成测试和去标识聚合。

CI 与 `tools/package_release.py` 均运行真实的 80% 全局门槛；覆盖率失败时停止正式打包。候选以 GitHub 草稿 PR 交付，不创建 v0.0.3 发布标签，不复用 v0.0.2 资产。不宣称所有质量门禁通过。

任何后续上线先匹配后端、再更新前端；新前端拒绝旧原始 token OAuth URL。回退旧后端时 Cookie 选择符不能单独认证，需要让浏览器重新登录。整个过程需分别验证权限、OAuth、刷新、流式连接和在途请求，不能通过重启旧单例清空共享租约。
