## 结论

外部审查的智境 ZJ-01 与 ZJ-02 在 v0.0.1 认证源码中成立。修复前新增四条安全验收断言，**四条均失败**，与审查描述一致；用户随后明确将这两项纳入 v0.0.2，当前候选的四条验收均已转为通过。原有文件哈希与构建检查只能证明变更边界，不能代替会话行为与凭证流向验证。

| 场景 | 修复前的合成复现 | 当前候选的验收结果 |
| --- | --- | --- |
| A 发出创建密钥 POST，切换 B 后旧请求返回 401 | 请求执行两次，重发使用 B 的合成凭证；没有另行发起刷新 | 只发送一次，返回会话已变化，B 的凭证与用户信息保持 |
| A 的请求晚到 401，当前 B 没有 refresh token | B 的本地凭证被删除 | 保留 B 的凭证 |
| A 的用户信息晚到，当前已经切换 B | token 属于 B，用户信息被写成 A | 保留 B 的用户信息及凭证 |
| 配置外部嵌入 URL | URL 查询参数含原登录 token | URL 不含原登录 token，iframe 与新窗口共用同一安全地址 |

运行：在 `frontend` 执行 `pnpm test:run --config vitest.review.config.ts`。四条原始验收源为 `frontend/src/__review__/p1.spec.ts`，保持原来的安全断言，没有使用 `it.fails` 或跳过。另有真实客户端、认证 API 与状态仓库的合成往返回归，覆盖正常登录/退出、刷新、不同 HTTP 方法、晚到结果、同账号再次登录和不同账号的刷新 singleflight。

复现只使用 `.example.test` 合成地址、合成账号和拦截适配器。没有向外部站点发送 token。没有证明后端权限绕过、真实泄露或已发生的线上损失。

## 修复范围与兼容处理

ZJ-01 已绑定请求发送、刷新协调、重发、用户状态写回与认证清除。会话代次、主体与凭证指纹用于识别不一致状态；发现混合写入时安全停止，不把它当作新身份继续请求。这是前端一致性保护，不代替服务端鉴权，也不宣称提供跨浏览器进程的数据库事务。

跨标签换号会清除旧页面和状态仓库缓存，避免新账号继续操作旧表格；正常同会话轮转不触发重载。本地浏览器实际完成了管理员标签保留、另一标签退出并登录合成成员的流程，原标签自动进入成员仪表盘且不再显示管理员导航。

ZJ-02 已停止自动传递原登录 token，清除常见凭证查询参数，来源追踪只保留来源 origin 与路径，并为 iframe 设置 no-referrer。已覆盖同域、外域、重定向入口和回调查询/片段。依赖旧参数的集成需要迁移；后续如需嵌入单点授权，应另行实现并联调限定目标、短时、单次消费的兑换票据，本轮没有交付该后端协议。

原兼容基线未被重置。变更前后摘要、相关测试夹具调整及行为说明见 `docs/security-changes-v0.0.2.json`。
