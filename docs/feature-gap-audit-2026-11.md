# 能力差距审计（2026-11）

这份文档回答一个问题：**和同类产品比，我们缺什么？**

它同时也是一份「查过、不是问题」的记录 —— 里面每一项都带验证方式和数据，
免得下一轮再从头查一遍。

对比对象取自公开资料（one-api / new-api / LiteLLM / Sub2API）：

- one-api：多上游 OpenAI 兼容聚合、令牌 / 额度 / 渠道管理
- new-api：one-api 分支，多用户与权限分配、按用户或团队核算成本
- LiteLLM：proxy 形态，按 key / team 的 tpm-rpm 限速与预算、fallback、路由、日志
- Sub2API：本项目的上游，订阅配额聚合与二次分发

## 一、结论先说

**核心能力不缺。** 七个候选差距逐一验证，六个是「已有」或「不是问题」，
剩下两个是真差距，但都不影响当前用户。

## 二、逐项验证

### 1. 扫描流量是不是有人在打我们？—— 不是，是一个正常客户

`175.27.132.225` 在访问日志里有 200 条 404（扫 `/.env`、`/.git/HEAD` 这类路径）。

但它同时有 **436 条 200**：`/`、`/login`、`/admin`、`/dashboard`、静态资源字体。
608 条请求里 2/3 是正常浏览。

**它背后是一个真实用户**，同一出口下另有扫描行为（浏览器插件或在跑的检测工具都可能）。
结论：**这个 IP 不能封**，防护规则里把它放进豁免名单是对的。

### 2. 并发限制是不是太紧？—— 不是，撞到的都自己恢复了

7 天内 113 次「并发已达上限」，涉及 5 个用户。

关键数据：**113 次全部在 60 秒内重试成功**。

```
refusals=113  retried_ok=113
```

挡住的是一次瞬时超限，不是一次失败。上限 3 是产品设定，没有数据支撑要改。

### 3. 配置备份在跑吗？—— 在跑，而且真的产出

`/etc/cron.d/gateway-config-backup` 每天 03:17 执行，备份目录
`/opt/gateway-ops/backups/` 的修改时间每次都跟着 cron 时间走（最近一次 `Nov 26 03:17`）。

### 4. 多语言是不是做了一半？—— 完整，还有完整性测试兜底

`frontend/src/i18n/locales/` 下 en / zh 两份逐模块一一对应（accounts、channels、ops、
overview、settings、resources……），并且有六个测试守着：键完整性、键冲突、消息编译、
以及若干功能专项。

组件里搜到的中文绝大多数是注释。**不是问题。**

### 5. 有没有每分钟请求数（RPM）限制？—— 有，两级

用户级 `rpm_limit` 与分组级 `rpm_limit`（分组优先，用户级兜底），
模型目录接口里也暴露了 `rpm_limit` 参数。

### 6. 上游失败会不会自动降级？—— 会，而且是三套机制

- 分组级 `FallbackGroupID`：主分组不可用时降到备用分组（带环检测）
- 无效请求兜底 `FallbackGroupIDOnInvalidRequest`：仅 anthropic / antigravity 分组可配
- 代理级 `ProxyFallback`：代理到期或失联时切到备用代理，并可回退

### 7. 请求了不存在的模型，用户知道该怎么办吗？—— 知道

错误消息里直接列可用模型：

```
Model "zzz-split2" is not supported by any configured account in this group.
Available models: codex-auto-revi...
```

7 天内 37 条里 24 条是我们自己的探针（`zzz-split2`、`zzz-probe-none` 等），
真实用户只有 4 次请求已下线的 `gpt-5.1`。

## 三、真差距（两条）

### 差距 A：按团队 / 用户的花费预算与告警

LiteLLM 有「按 key / team 的预算上限 + 接近上限告警」。我们目前是**配额扣减**
（订阅额度），不是**花费预算**（按金额），也没有「用到 80% 提前告警」。

对当前用户不构成问题：我们是订阅制，额度是分发的，不是自付账单。
**触发条件**：如果要面向外部客户售卖或按金额结算，这条必须补。

### 差距 B：按 token 数（TPM）限速

我们只有 RPM（请求数）和并发数。LiteLLM 有 tpm/rpm 双维度。

对当前用户不构成问题：单人并发 3 已经压在很低的位置，token 吞吐自然受限。
**触发条件**：出现「少请求、巨上下文」的用法（长文档分析、批量推理），
这时 RPM 挡不住，才需要 TPM。
